# AIs & Ears audit — 2026-11-06

## Verdict

**The native project is a plausible SDK54 iPhone13 build candidate after these fixes, not a proven installable IPA and not ready for paid/public release.** The most immediate connection failure is a confirmed client lifecycle bug. Main also lacks the already-working bridge compatibility changes. Android live voice and native device-screen capture remain unimplemented; an APK export cannot make them work.

Scope: latest `origin/main` **390e835**, plus existing `fix/get-working` **bdf8eb9** (PR#1), integrated without changing main. Work is on `fix/audit-2026-11-06`. No Render deploy, EAS build, signing operation, certificate/profile creation, Apple login, store action, live model session, payment or checkout was performed. No credentials were read from secret files or committed.

Source citations labeled `390e835` show the actual audited baseline; other citations point to fixes on this audit branch. Severity reflects impact, not a claim that an exploit was demonstrated. All source-code findings below are **confirmed** unless specifically marked unknown, likely or an account/deployment gate.

## End-to-end connection / hearing / seeing trace

1. **Native access:** Packages POSTs `/api/checkout` and opens Whop; successful return must carry a genuine membership ID and tier. Conversation verifies it at `/api/checkout/verify`, or takes an already-issued bridge session UUID. The native checkout placeholder still blocks a trustworthy real purchase flow.
2. **Middlemain bridge:** Middlemain POSTs `/api/bridge/session` with a bridge secret; returned UUID authorizes `/api/grok-live`, `/api/grok-vision`, `/api/music-analyze`. AIs & Ears native UI itself has no bridge-key entry screen. Native iPhone testing needs a valid session handoff or a separately implemented internal test-access path, not an embedded production bridge secret.
3. **Socket:** app connects to Render `/api/grok-live?sessionId=...`; server validates DB session/key, opens xAI upstream, normalizes legacy protocol, returns `connected`. Previously native status changes immediately closed this socket. Actual upstream/model readiness and quota remain separate from local WebSocket-open.
4. **Hearing:** iOS records500ms WAV chunks -> legacy FileSystem read -> strict WAV/PCM validation -> raw PCM24kHz/mono/int16 append -> xAI VAD. Stop/restart-per-chunk introduces recording gaps; this is not continuous native streaming. Device test must check lost syllables, Bluetooth route, speaker echo and TTS feedback. Android voice is still intentionally blocked, not fixed by the AAC music path.
5. **Replies:** native displays text/audio-transcript events and uses device TTS, **not xAI raw voice playback**; browser plays PCM reply audio. Native TTS side effects were moved out of React state updater functions, with fallback for final-only transcript events. Stop reply/Stop all media paths are separate from retrying a session.
6. **Seeing:** camera snapshot or browser screen frame -> POST `/api/grok-vision` -> stateless vision model -> display result. It is not the voice model's persistent visual memory. Native auto-vision remains web-only in copy; native screen-sharing is absent.
7. **Music:** browser/iOS raw PCM or Android4sec AAC/M4A -> `/api/music-analyze` -> deterministic RMS/ZCR/chroma/BPM/key heuristics -> brief session-instruction context. **No song fingerprint database, artist/title lookup, lyric recognition or reliable instrument recognition exists.** Music/speech classification and BPM/key are estimates; synthetic decoder success is not an accuracy benchmark. Ambient microphone is not internal device audio.
